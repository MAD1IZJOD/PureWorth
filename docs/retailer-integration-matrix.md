`AUTHORIZED_ACCESS_AVAILABLE` is reserved for a provider with documented rights and configured, verified access for PureWorth. `UNSUPPORTED` means a documented capability is unavailable in the connector. Neither status is inferred merely from absent public documentation.

## Caching, attribution and use restrictions

Amazon's [current programming guidance](https://affiliate-program.amazon.in/creatorsapi/docs/en-us/concepts/best-programming-practices) describes field-specific caching and prohibits caching customer information. Its [license guide](https://affiliate-program.amazon.com/creatorsapi/docs/en-us/license-agreement) points India users to the [India agreement](https://affiliate-program.amazon.in/help/operating/agreement). Review the applicable agreement, price timestamps/disclaimers, link preservation and affiliate disclosure before enabling access. No Amazon TTL is installed in this app: rights and freshness are separate, and neither is established for PureWorth.

For Swiggy, retention, attribution, scope and quotas must follow the approved partner contract. For Flipkart, published terms require specific attention to competitive use and branding; do not interpret documentation as permission. For Blinkit, Zepto and BigBasket, caching and commercial comparison rights are unverified. ONDC storage and fulfillment rights depend on network policy, domain protocol and participating sellers. All real-provider cache policies therefore default to **no caching**.

## First legitimate connection gate

1. Record provider approval for this exact comparison use, permitted fields, locations, caching/retention and disclosures.
2. Confirm current official documentation, endpoints, quotas and credentials in the approved environment.
3. Implement server-only authentication and explicit endpoint allowlisting; never accept a fetch URL from a browser.
4. Contract-test response normalization, stock/serviceability, taxes, eligibility, fee completeness, expiry and partial failures.
5. Configure authorized capability states, feature flag and permission-bounded cache/freshness policies. Enable only capabilities actually granted.
6. Review security, attribution and evidence with the owner before a limited live trial. Ordering/payment remain a separate future scope.
